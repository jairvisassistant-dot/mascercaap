## Hallazgos de Seguridad en los Cambios

### Positivos ✅

1. **Webhook signature verification** — Implementación correcta con `crypto.timingSafeEqual` para prevenir timing attacks. Graceful degradation cuando `WHATSAPP_APP_SECRET` no está configurado.
2. **Zod schema validation en webhook** — Valida shape del payload antes de procesar.
3. **PII sanitization en logs** — Webhook y lead routes usan `err.message` en vez de objeto completo.
4. **Admin auth centralizado** — Todas las admin routes ahora usan `requireAdminAuth()` consistente.
5. **Env var guards** — Login route y webhook GET fallan explícitamente con 503 si env vars faltan.
6. **HTML escaping centralizado** — `escapeHtml` en módulo compartido, no duplicado.
7. **Privacy consent checkbox** — ContactForm ahora requiere consentimiento explícito (Ley 1581/2012).
8. **Upload rate limiting** — Admin upload route ahora tiene rate limiting (10 uploads/IP/5min).
9. **localStorage try/catch** — CookieConsent protege contra modo privado del navegador.

### Precauciones ⚠️

1. **`lib/sanitize.ts` es untracked** — Si se commitea sin el archivo, las routes de contact y orders romperán. Debe incluirse en el mismo commit.
2. **`findAnswer` signature change** — Si algún caller no se actualizó a `findAnswer(query, lang, faqData)`, habrá runtime error. Verificar todos los consumidores.
3. **`supabase` shared client puede ser null** — Todas las rutas que lo usan tienen guards, pero verificar que ningún nuevo código asuma que siempre está disponible.
4. **`WHATSAPP_APP_SECRET` fallback** — `verifySignature` retorna `true` si el secret no está configurado. Esto es intencional para dev pero debe documentarse como blocking para producción.
5. **Imágenes PNG sin tracking** — `Iva.png`, `Ubicaion.png`, `Zumos.png`, `efecto.png` en root del proyecto. Si son productos nuevos, deben moverse a `public/imgs/` y convertirse a WebP. Si son temporales, deben eliminarse.
