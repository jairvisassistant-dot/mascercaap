### ARCH-05 — `app/layout.tsx` desacoplado del proxy ✅ RESUELTO

**Antes:**
```ts
const lang = hdrs.get("x-lang") === "en" ? "en" : "es";
```

**Después:**
```ts
const ckrs = await cookies();
const cookieLang = ckrs.get("NEXT_LOCALE")?.value;
const headerLang = hdrs.get("x-lang");
const lang = cookieLang === "en" || headerLang === "en" ? "en" : "es";
```

El `NEXT_LOCALE` cookie es la fuente primaria (lo setea el language switcher del usuario). El header `x-lang` del proxy queda como fallback para primera visita. Elimina el SPOF: si el proxy falla, los usuarios con preferencia guardada no ven el idioma incorrecto.

**Commit:** `e4f2119`

### ADMIN-03 — proxy.ts de admin-app interceptaba requests a `/imgs/` ⚠️ Bug crítico encubierto

**Root cause:** El matcher del proxy del admin-app no excluía `/imgs/`. Next.js image optimization hace una request HTTP interna a `/imgs/Logo.webp` para leer la fuente. El proxy interceptaba esa request, veía que no empezaba con `/admin`, y redirigía a `/admin/login`. El optimizador recibía HTML en vez de una imagen → `received null`.

**Fix:**
```
antes:  /((?!api|_next/static|_next/image|favicon.ico).*)
después: /((?!api|_next/static|_next/image|favicon.ico|imgs).*)
```

**Commit:** `dd83e8e`

### ADMIN-04 — tsconfig.json del main app compilaba admin-app/
